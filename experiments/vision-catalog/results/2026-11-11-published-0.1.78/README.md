# Published LLaVA JBang consumer proof

Both Q4_K_S and Q4_K_M passed on 2026-11-11 using ModelJars 0.1.78, Models 0.5.19,
Vectors 0.1.34, JBang 0.143.0, and Temurin 25.0.5 on the admission EPYC 7R13 host.
This is the post-publication distribution smoke: one frozen image/question per variant.
The full eight-gate qualification and three-case released API/CLI checks remain in the
[released evidence](../2026-11-11-released-0.1.78/) and its linked backend reports.

The unchanged sources generated by the released CLI were run through ordinary JBang
resolution with a new Maven/JBang cache for this two-variant run and a new model cache
per variant. No staged marker, explicit classpath, or native-library override was used.
The only application property was `modeljars.cache`. Both answered `2` to frozen case
`vqav2-132415014` ("How many pieces of pizza are there?"). This smoke does not remeasure
qualification performance; load times include fresh weight installation.

`run-published-demos.py` is the exact executed helper. Each `published-demo.json` records
the source and prior release-report hashes, public marker POM/JAR URLs and SHA-256s,
resolved cache paths, five checked runtime JAR hashes, exact command, and successful exit.
The helper checked both the expected answer and those hashes before emitting `passed`.
Logs are preserved losslessly as `.log.gz`; caches, weights, and runtime binaries are omitted.
The generated source hash links to the byte-identical source in the released evidence.
